# NETWATCH NG APT repository setup

The signed repository publication workflow is prepared in
`.github/workflows/publish-apt.yml`. It publishes only after a GitHub
Release with a `v2.*` tag is published.

The workflow is not operational until GitHub Pages and the signing secrets
below are configured by the repository owner.

## 1. Create a dedicated archive signing key

Create a dedicated GPG key for APT repository signing. Keep the private key
outside the repository and protect it with a strong passphrase.

```bash
gpg --full-generate-key
gpg --list-secret-keys --keyid-format=long
gpg --armor --export-secret-keys YOUR_KEY_FINGERPRINT > netwatch-ng-archive-private.asc
gpg --armor --export YOUR_KEY_FINGERPRINT > netwatch-ng-archive-public.asc
```

Do not commit either key file.

## 2. Configure GitHub Actions secrets

In repository Settings → Secrets and variables → Actions, create:

- `APT_GPG_PRIVATE_KEY`: the ASCII-armored private key contents.
- `APT_GPG_KEY_ID`: the full signing-key fingerprint.
- `APT_GPG_PASSPHRASE`: the key passphrase.

The workflow imports the key only during the release job. It does not
write the private key into the repository or Pages artifact.

## 3. Enable GitHub Pages

In repository Settings → Pages, set the deployment source to **GitHub Actions**.

The workflow uses the `github-pages` environment and requires `pages: write`
and `id-token: write` permissions.

## 4. Publish a release

After the package passes the Debian 12/13 build and installation workflow,
create a GitHub Release using a `v2.*` tag, for example `v2.0.0`.

The publication workflow then:

1. Rebuilds the Python package and runs its tests.
2. Builds the Debian `.deb` package.
3. Generates the `Packages`, `Packages.gz` and `Release` indexes.
4. Signs `InRelease` and `Release.gpg`.
5. Publishes the repository and public key through GitHub Pages.

Do not publish a stable release while required NG features or release tests
remain incomplete.

## 5. Install on Debian/antiX amd64

After the first Pages deployment succeeds, add the public key and repository:

```bash
curl -fsSL https://sudomarc.github.io/NETWATCH/public.key \
  | sudo gpg --dearmor -o /usr/share/keyrings/netwatch-ng-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/netwatch-ng-archive-keyring.gpg] https://sudomarc.github.io/NETWATCH/ stable main" \
  | sudo tee /etc/apt/sources.list.d/netwatch-ng.list

sudo apt update
sudo apt install netwatch-ng
```

The repository index generated by this workflow targets Debian `amd64`
systems, including the user's x86_64 antiX/Debian target. The `.deb` itself
is architecture-independent Python code.

The URL and package signature must still be verified after the first real
Pages deployment. Until then, use the `.deb` artifact produced by the
Debian package workflow.
